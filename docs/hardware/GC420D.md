# Reference hardware — Zebra GC420d

This document separates user-confirmed installation facts, documented model facts and unobserved unit settings. No physical printer has been accessed while preparing this revision.

## Evidence and identification

The maintainer reports a **GC420d connected by USB**, with **4×6-inch pre-cut labels**, operating in **tear-off**, with **no cutter**. Previously, `lpr -l` could deliver ZPL successfully through the existing queue. This does not prove our new backend works.

Zebra's public GC420d support page identifies the direct-thermal model [R27](../REFERENCES.md#r27). Its GC420 d/t technical specification lists 8 dots/mm, a 0.125 mm dot pitch, a 104 mm maximum print width, programmable speeds 2/3/4 inches per second, gap/black-line/notch sensing, and bidirectional USB [R26](../REFERENCES.md#r26). The combined d/t sheet does **not** make thermal-transfer/ribbon features available on the d model.

Do not import GK420d, GC420t or newer ZD-series profiles as aliases. Read-only discovery should resolve this actual unit; firmware, serial, USB path and present settings remain local observations. Preserve unknown query capability; no modern Link-OS, SGD, network service or particular USB status channel is assumed.

## Geometry oracle (chosen rounding policy)

Use rational/decimal physical arithmetic. For this documented pitch and nominal label face:

```text
4 in × 25.4 = 101.6 mm; 101.6 × 8 = 812.8 dots
6 in × 25.4 = 152.4 mm; 152.4 × 8 = 1219.2 dots
nearest integer, positive half away from zero: 813 × 1219 dots
bytesPerRow = ceil(813 / 8) = 102
packedBytes = 102 × 1219 = 124338
padding = 3 white low-order bits in the final byte of each row
104 mm × 8 dots/mm = 832 dots of nominal maximum head width
```

These are **derived planning/test values**, not a measured printable region. At 8 dots/mm, the nearest-dot face differs by +0.025 mm in width and -0.025 mm in height; placement/stock variation needs a separate physical tolerance. A 203×4 by 203×6 raster (812×1218) is a valid synthetic test but is not the geometry oracle for this dot pitch.

A driver may advertise nominal 203 DPI where the print system requires an integer. Keep that advertised value separate from the renderer's physical pitch. Prove document geometry and any upstream rasterization; do not resample an already-correct integer-DPI raster without an explicit tested transform.

The 832-dot head extent is not the 813-dot label face, and neither establishes liner width or X origin. Nominal face height is not label pitch including the gap. Do not add an invented gap to `^LL`, assume zero margins, stretch to the head width, or alter printer width/origin blindly. Setup must validate the actual imageable region and media tracking.

## Output and memory

Use bounded graphic bands within **one** label format, not one label per band. The documented `^GF` field-size limits apply [R07](../REFERENCES.md#r07). A proposed initial decoded band cap of 32,768 bytes gives 321 rows at 102 bytes/row; 1219 rows partition as 321 + 321 + 321 + 256. This is a conservative project choice, not a manufacturer-certified memory budget. Test an independent decoder and the device before enabling compression.

Do not infer the entire advertised SDRAM is available to graphics or queue unbounded downloads in printer memory. Start with documented plain graphic output; gate compression and stored-image optimization on firmware evidence. Never clear printer storage or save persistent configuration during an ordinary job.

## Controls and defaults

| Control | Baseline behavior |
|---|---|
| Thermal method | Direct thermal only; reject ribbon/transfer requests |
| Finishing | Tear-off only for this installation; reject cut, peel, rewind and cut-count requests |
| Cutter | Confirmed not installed; no cutter commands or tests on this unit |
| Peeler | Not separately inventoried; selected setup disables it; do not invent hardware presence/absence |
| Print speed | Documented selectable values 2, 3, 4 ips; reject unsupported values, do not clamp |
| Darkness | Typed ZPL setting, distinct from image threshold; current value unknown; range/protocol mapping needs documented/model validation [R12](../REFERENCES.md#r12) |
| Tracking | Pre-cut suggests web/gap but is not proof of sensing; preserve/confirm existing settings |
| Position/length | Calibrated profile values only; no arbitrary factory default claims |
| Status | Unknown until a supported bounded query path is verified; USB writes do not confirm a label printed |

Initially preserve the working device settings for an explicitly authorized baseline test. Before deterministic product qualification, read/confirm and publish explicit validated defaults, or expose `leave unchanged` with its uncertainty. Never turn missing speed/darkness into zero. Do not auto-calibrate or auto-save settings.

## USB and ownership

Resolve the actual existing connection without inspecting proprietary driver packages. Host USB enumeration and queue metadata are useful; a bidirectional USB specification does not establish that our chosen backend exposes reliable status reads. Keep serials/URIs private. Do not switch to raw TCP to bypass USB integration work.

All project queues share the device coordinator through actual delivery and status boundaries. The original unrelated queue cannot be assumed to participate in that lock. Keep it installed, but require no competing raw/original-queue jobs during a controlled project session. Cancellation must not blindly send a device-global cancel that disrupts unrelated work.

## Qualification

Use the [first-run plan](../validation/GC420D-TAHOE-FIRST-RUN.md). Physical checks cover alignment, scans, actual native/extraction workflows, copies/order, interqueue isolation, disconnect/uncertain delivery, paper/head states and restart. Cutter, peel-wait and ribbon-out tests are **not applicable to this installed baseline**; their generic implementation/evidence remains separate work for suitable hardware.
