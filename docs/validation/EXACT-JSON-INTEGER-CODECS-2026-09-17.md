# Exact JSON integer identity codec integration

Repairs the manual codec defect documented in JSON-INTEGER-IDENTITY-INVESTIGATION-2026-09-17.md. Advances M3-AC02 and M4-AC08 software validation without creating a complete per-ID or hardware acceptance pass.

Nearest independent constraint: typed integer identities and settings must retain exact numeric value through JSON admission, including fractional rejection before any floating coercion. All seven enumerated portable codecs now decode through TokenPreservingJSON and obtain integers from retained numeric tokens: WorkflowProfileJSON, PrinterProfileJSON, ResolvedJobTicketJSON, ActiveVirtualQueueJSON, FinishingQueueJSON, AcceptedJobStateJSON and VirtualQueueJSON. The shared PrivatePhysicalGeometryJSON and PrivateOffsetJSON readers use the same admission while retaining their independent signed bounds. The native WorkflowProfileStore qualification manifest validates schema/revision through exact tokens as well.

TokenPreservingJSON is public only to share the admission boundary between LabelCore and LabelMac. Its number type exposes exact integer and finite floating conversion; floating geometry remains a separate typed operation. UTF-8 BOM and BOM/detected UTF-16/32 input are normalized without numeric coercion, preserving previous encoding admission. Input, token, depth and node budgets remain finite; duplicate decoded keys reject. Existing codec wire schemas, encoding order, canonical checks, missing/invalid-field error mapping and boolean distinction are preserved. The encoder emits the same wire data for previously valid typed profiles; large identities no longer round or fail solely at the Double boundary. No device setting range is widened.

Regressions enumerate values 9007199254740993 and Int.max across all seven portable codec sites. Native qualification/save/reload also covers Int.max. Workflow input rejects large fractional tokens, fractional near-integer decimals, signed overflow and booleans while accepting integral decimal/exponent forms. Encoding tests cover UTF-8/16/32 and UTF-8 BOM. The original regression previously reproduced changed identity and invalidType on Int.max. Faulting the shared conversion back to Double caused all seven portable regression methods to fail: 18 failed assertions/errors, exit 1. Restored source passed the seven cases exit 0.

Observed focused validation: full LabelCore debug/release each passed 299 tests exit 0. WorkflowProfileStoreTests debug/release each passed 21 native tests exit 0. An initial integration run failed 11 assertions/errors because the two private geometry/offset readers still expected NSNumber; those shared readers were included, and the full suite then passed. No failing assertion or acceptance criterion was removed.

The full native CI-equivalent sequence is pending at this implementation checkpoint. No new whole-system baseline or hosted CI pass is claimed yet. Linux validation is NOT RUN on this Mac. Runtime is macOS 27.0 build 26A428 ARM64, Apple Swift 6.4; deployment remains macOS 26 minimum, without claiming retail-host or physical compatibility.

No printer I/O, queue change, administrator action, manual GUI, merge or release occurred. The frozen M1 Part B candidate remains unchanged. Installed spooler ownership/options/uncertain-retry behavior, privileged helper installation and physical GC420d USB output/status/finishing remain their separate gates. Older source-bound acceptance records remain historical; the scalar/traversal dependency reports describe earlier checkpoints, not current complete codec integration evidence.
